Coding guidelines

AI tools can generate code. Teams establish that the code answers their question correctly.

Think first, then prompt

Define the inputs, expected outputs, assumptions, and checks before generating code. Describe what would count as a correct result.

Work in small steps

Implement a small part of the analysis, run it, and inspect the result before proceeding. Begin with a small region, time interval, or simplified case before scaling up.

Check correctness

Test a case with a known or independently reasoned answer. Inspect units, coordinate systems, data ranges, missing values, and alignment. Check how the code behaves with empty inputs or other relevant edge cases. Running successfully does not establish correctness.

Take responsibility for the analysis

Teams are responsible for the behavior and correctness of submitted code, including assumptions and silent failures. Consider costs, data access permissions, and the consequences of changing files or environments.

Explain the work

Be able to explain what each major step does, why it answers the question, what assumptions it relies on, and where it could give misleading results.

A practical workflow

  1. Write a short specification.
  2. Develop a plan that matches it.
  3. Implement one step at a time.
  4. Add a verification check after each step.
  5. Scale up after the small case is correct.

What to include

Include a Verification section describing what you checked and observed, and a Known limitations section describing where results may be incomplete or misleading. Keep data sources and external code attribution with the analysis.

If a result is difficult to explain, reduce the scope and inspect intermediate outputs. Ask for help with the relevant code, error text, and checks already attempted.
